# STEP English — موقع مذاكرة ومنافسات لاختبار STEP

موقع ثابت (HTML/CSS/JS) + دوال خادم صغيرة على Vercel (مجلد `api/`) + قاعدة بيانات Redis (Upstash عبر Vercel Marketplace) للحسابات والنقاط والتحديات.

## التشغيل محليًا
```bash
node dev/server.js
```
ثم افتح http://localhost:8765 — الخادم المحلي يستخدم قاعدة بيانات في الذاكرة (تُمسح عند إعادة التشغيل). صفحات المذاكرة تعمل أيضًا بفتح `index.html` مباشرة، لكن الحسابات والمنافسات تحتاج الخادم.

## النشر على Vercel (مرة واحدة)
1. أنشئ حسابًا في https://vercel.com ثم في هذا المجلد:
   ```bash
   vercel login
   vercel --prod --yes
   ```
2. من لوحة Vercel: المشروع → **Storage** → **Create Database** → **Upstash for Redis** (الخطة المجانية) → **Connect Project**. هذا يضيف متغيرات `KV_REST_API_URL` و `KV_REST_API_TOKEN` تلقائيًا.
3. أعد النشر ليقرأ الخادم المتغيرات:
   ```bash
   vercel --prod --yes
   ```
لتحديث الموقع لاحقًا: عدّل الملفات ثم `vercel --prod --yes`.

## البيانات (هنا تُضاف النماذج الجديدة)
- `data/questions.js` — بنك أسئلة القواعد: `{id:"g181", topic:"tenses", q:"...", opts:[...4], a:1, ex:"الشرح", src:"real"}`. `topic` من `TOPICS`. `type:"error"` لأسئلة تحديد الخطأ (الأجزاء بين `<u></u>`).
- `data/vocab.js` — المفردات: `{w:"word", s:["synonym"], ar:"المعنى", orig:"المرادف القديم في التجميعات إن صُحّح", skip:true}`.
- `data/collections.js` — التجميعات (مولَّد من ملفات PDF بسكربت استخراج يعتمد على «الخط تحت الإجابة»): `COLLECTIONS.{listening,grammar,reading}.models[].items[]` — `{q,o:[...],a:index}` أو `{q,a:'answer',o:'others',ar}` أو `{rec}`/`{t,te}`/`{n}`.
- `data/reading.js` — قطع القراءة: `{id:"p7", title, ar, note, text, qs:[{q, opts, a, ex}]}`.

## إنقلش عام (`general.html`)
وحدة مستقلة عن STEP لتطوير اللغة من A1 إلى B2. تطبيق صفحة واحدة يعمل بالتوجيه عبر `#/`:
- المفردات: `data/general/vocab-a1.js … vocab-b2.js` (46 موضوعًا، 1127 كلمة بصيغة `[الكلمة, المعنى, النوع, مثال, ترجمة المثال]`). ألعاب: بطاقات حفظ، اختبار معنى، ترتيب حروف، طابق، أكمل الجملة، جولة سرعة.
- القواعد: `data/general/grammar-1.js` و `grammar-2.js` (26 درسًا بأسلوب الاستخدام لا المسميات: متى تقولها، قوالب جاهزة `frames` تعبّيها وتنطقها، `speak` قلها عن نفسك، أمثلة، أخطاء شائعة، تدريب؛ الاسم الأكاديمي في `jargon` للمرجع فقط).
- المحادثة: `data/general/dialogues.js` (21 حوارًا مع نطق وتسجيل صوتي عبر Web Speech API — التعرف على الصوت يعمل في Chrome/Edge).
- المسار: `data/general/units.js` (46 وحدة قصيرة، وحدة لكل موضوع: مفردات + درس قواعد إن وُجد + حوار إن وُجد + اختبار وحدة من ١٢ سؤالًا).
- النقاط: XP محفوظة محليًا في `step_gen`، وتُرسل للخادم عبر `/api/result` بوضع `general` لتدخل في لوحة المنافسة.

## قسمان منفصلان
- `index.html` صفحة اختيار: **إنقلش عام** أو **تجهيز STEP**. `step.html` هي رئيسية ستيب (كانت index سابقًا).
- القائمة العلوية والشريط السفلي يتغيّران حسب القسم (`NAV_STEP` / `NAV_GEN` / `NAV_LANDING` في `assets/app.js`، ودالة `section()` تحفظ آخر قسم في `step_section`). الصفحات المشتركة (حسابي، تنافس) تتبع آخر قسم زاره المستخدم.

## مكتبة القصص (`library.html`)
- البيانات في `data/stories/lvl-a1.js … lvl-c2.js`: `{id,lvl,d,kind,title,ar,author,origin,intro,paras:[{en,ar}],glossary,qs,moral}` وتُدفع كلها إلى `window.STORIES`. الترتيب داخل المستوى بحقل `d` (الأسهل أولًا).
- **المحتوى الحالي:** ٥٦ قصة (A1 ١٠، A2 ١٠، B1 ١٠، B2 ١٠، C1 ٨، C2 ٨) بمجموع ٣٩٬٤١٢ كلمة إنجليزية، كلها مسجّلة صوتيًا.
- الصوت: ملفات `audio/stories/<id>.mp3`، وتوقيت كل جملة في `data/story-times.js` بصيغة `[بداية, نهاية, رقم الفقرة, من حرف, إلى حرف]` ليُلوّن القارئ الجملة الحالية. إذا لم يوجد ملف صوت لقصة يقرأها صوت المتصفح تلقائيًا.
- **فحص الدروس:** `node tools/check-lessons.js` يتحقق أن كل أداة تركيب تختبرها أسئلة الدرس مشروحة فعلًا في «متى تقولها» أو «شكل الجملة» أو القوالب.
- **لإضافة قصص جديدة:** أضف الملف في `data/stories/`، ثم `python tools/story-audio.py <id> <id> …` (يحتاج `pip install edge-tts`) لتوليد الصوت والتوقيت، ثم `python tools/story-audio-shrink.py 32k` لتخفيف الحجم (يحتاج `pip install imageio-ffmpeg`). حد النشر في Vercel للخطة المجانية ١٠٠ ميغابايت لكل نشرة، والمشروع الآن ~٥٦ ميغابايت.
- لكل مستوى صوت قارئ مختلف (A1 أبطأ وأوضح، وصولًا إلى C2 بسرعة طبيعية).
- أسئلة الفهم تُرسل إلى `/api/result` بوضع `reading` مع معرفات `st-<storyId>-<i>` فتدخل النقاط في المنافسة بقاعدة «نقطة واحدة لكل سؤال».

## النقاط والفعاليات والبطولة
- **قاعدة النقاط (بدون تكرار):** كل سؤال يعطي نقطته مرة واحدة فقط لكل مستخدم — أول مرة يجيبه صح. الخادم يحفظ معرفات الأسئلة المكتسبة في `earned:<user>` (Redis SET)، والعميل يرسل `ids` الأسئلة الصحيحة مع كل نتيجة. إعادة الاختبار تعطي فقط نقاط الأسئلة التي لم تُكسب من قبل. مراجعة الأخطاء وبطاقات الحفظ لا تعطي نقاطًا.
- **الفعاليات (نقاط ×٢):** كلها في `data/events.js` (يقرأه المتصفح والخادم معًا، توقيت الرياض): فعاليات متكررة (الجمعة كامل اليوم، ساعة الذهب ٩–١٠ مساءً) وفعاليات خاصة بتاريخ. المضاعف يُطبّق في الخادم على النقاط الجديدة فقط.
- **البطولة الشهرية:** معرّفة في نفس الملف (`tournament`: العنوان، الجائزة، من/إلى، مفتاح الشهر). تُحسم بلوحة `lb:month:YYYY-MM`. تظهر في شريط الفعاليات بكل الصفحات وفي تبويب «البطولة» بصفحة المنافسات. لتغيير الجائزة أو المدة عدّل `data/events.js` وأعد النشر.
- **الأصوات:** `assets/sfx.js` يولّد الأصوات بـ Web Audio (ضغطة، صح، خطأ، تكّات المؤقت في آخر ١٠ ثوانٍ، انتهاء الوقت، فوز، عملة النقاط). زر كتم في الشريط العلوي، ويُحفظ في `step_sfx`.

## الخادم (`api/`)
`register`, `login`, `me`, `result` (حفظ نتيجة + نقاط + ترتيب)، `leaderboard`, `challenges` (قائمة/إنشاء)، `challenge?id=` (نتائج تحدٍ)، `progress` (مزامنة الإتقان مع الحساب). المكتبات في `lib/` (Redis عبر REST، جلسات موقّعة، كلمات مرور scrypt). لا توجد تبعيات npm.

## التخزين
- Redis: `user:{u}`, `stats:{u}`, `results:{u}`, `lb:total`, `lb:week:{YYYY-Www}`, `challenge:{id}`, `challenge:{id}:res`, `progress:{u}`.
- المتصفح: `step_auth` (الجلسة)، `step_prog` (ذاكرة الأسئلة والإتقان)، `step_history`، `step_vocab_known`، `step_theme`.
